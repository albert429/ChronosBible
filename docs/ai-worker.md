# Cloudflare AI runtime

AI is optional. The reader stays a static application; only `/api/ai/*` runs Worker code. Vercel disables the AI feature. Production's release gate is closed in `scripts/hosting/cloudflare-app.mjs` and `wrangler.json` until dev acceptance is recorded.

## Architecture and public contract

`worker/index.ts` routes requests to one SQLite-backed `AiCoordinator` per environment. `worker/` owns credentials, prompts, trusted context, provider calls, stream parsing, atomic quotas and shared answers. `src/domain/ai/` holds pure contracts; `src/data/ai/` holds the same-origin API client. Browser imports of Worker code are rejected by ESLint and `npm run layers`.

- `GET /api/ai/v1/status`: `available`, `cacheRevision`, device `limits` and `usage`, and `resets.device` (Cairo) / `resets.provider` (UTC), as epoch milliseconds. Availability describes runtime configuration; generation can still be refused by an allowance or concurrency limit.
- `POST /api/ai/v1/answer`: `{ verseId, chip, question?, fresh?, turnstileToken }`. `chip` is `explain`, `words`, `background` or `ask`. Only `ask` accepts a question, cleaned and bounded to 3–200 characters. The entire UTF-8 body is bounded to 16 KiB, including chunked bodies. Extra fields are rejected.
- SSE events: `meta` (request ID, cache hit and model attribution), `activity`, `delta`, `quota`, `done`, `error`. **`delta.text` is a replacement snapshot**, bounded to 6,000 characters; this lets sanitization revise an incomplete prefix without revealing hidden reasoning. `done` includes `provider`, `model`, and `finish: stop | length`. Errors carry normalized `kind` and optional epoch `retryAt`; HTTP errors wrap those in `{ error }` and include `Retry-After` when applicable.
- All API responses are `no-store`. The service worker passes AI requests through, including navigation requests. Internal cancellation messages are sent only through the Durable Object binding, never through a public endpoint.

The Object resolves the canonical verse against the book catalog, loads its full chapter through `ASSETS`, derives canonical headings and uses three preceding/following verses, clipped at chapter edges. All reading tracks therefore share context. Translations and original-language resources are optional, with four simultaneous asset reads maximum and the existing 30,000-byte compressed / 256 KiB decoded word limits. An optional-resource failure prevents shared caching. `ai-data-version.json` is generated by Vite from the canonical Bible/study content hashes.

The Arabic prompt remains unchanged. Server-only model order is `google/gemma-4-31b-it:free`, `google/gemma-4-26b-a4b-it:free`, `openrouter/free`; output is limited to 2,000 tokens. Each fallback is a separate reserved call. Neither Gateway nor OpenRouter provider fallback may retry automatically. Authentication, quota, rate and storage failures stop fallback. No fallback occurs after text arrives. Initial wait is 25 seconds, hidden activity may extend it to 60 seconds, idle timeout is 20 seconds, and the complete request has a 120-second deadline.

## Accounting, cache and privacy

| Limit                                | Production | Dev |
| ------------------------------------ | ---------- | --- |
| Provider dispatches / UTC day        | 40         | 10  |
| Provider dispatches / rolling minute | 15         | 5   |
| Concurrent generation                | 3          | 1   |

Each browser gets ten generated answers and twenty provider attempts per Cairo day, with one generation at a time. Reservations include context loading, expire after 125 seconds, and count an answer at the first visible text. Attempts are charged before dispatch, including failed calls. Daily device accounting is attached to the reservation's Cairo day. Clearing cookies can create a new anonymous browser; aggregate provider limits remain authoritative. Both environments must use one **dedicated** OpenRouter account with no other consumers; separate keys do not multiply the account allowance.

A signed `__Host-chronos-ai` cookie lasts thirty days (`Secure`, `HttpOnly`, `SameSite=Strict`, host-only). Counters use HMAC pseudonyms; burst protection uses a daily HMAC of the IP, twenty requests per rolling minute. No IP or cookie is sent upstream. Quota identifiers are deleted after 48 hours by request cleanup and an hourly alarm. Storage failure refuses generation. Cache hits do not spend generation quota and remain usable at that quota limit.

Only completed, non-truncated preset answers with complete context are shared: seven days, at most 1,000 entries, keyed by canonical verse, action, prompt/model revision and Scripture/study hashes. Concurrent requests for the same preset key receive `busy` with a short retry time. Typed questions and partial/failed answers are never stored. Bump `PROMPT_VERSION` whenever prompts or models change. Browser answer cache v2 includes the data revision; the existing device off switch and all profile/progress keys are preserved.

Every network answer, including a shared-cache hit, requires a fresh Turnstile token. Siteverify must report success, the exact configured hostname, `ai_answer` action and a challenge timestamp within five minutes. Tokens are also atomically recorded to reject replay. The widget loads only after a device-cache miss and mounts inside the study dialog. POST origin must exactly match `AI_ORIGIN`.

The server constructs an explicit upstream header allowlist. Gateway receives `cf-aig-max-attempts: 1`, `cf-aig-skip-cache: true`, and `cf-aig-collect-log-payload: false`. Application logs include only random request ID, duration, cache result and normalized error code. Configure Gateway metadata logging without payloads or Logpush payload export. Model providers may retain submitted text, as disclosed in Arabic in the panel and About.

## Local work and verification

Use Node 22 and `npm ci`. Wrangler, Miniflare, Workers types and the bundler are pinned. Worker output lives in ignored `artifacts/worker/`, never `public/` or `dist/assets/`.

For live local development, generate a build, put secrets in ignored `.dev.vars.dev` using `.dev.vars.example`, configure the dev Gateway identifiers and local `AI_ORIGIN` through a local Wrangler config, then run `npm run worker:dev`. Vite proxies `/api/ai/` to port 8787; its local origin must match that runtime setting. Enable the UI with `VITE_AI_ENABLED=true` and `VITE_TURNSTILE_SITE_KEY`. Never copy real keys into `VITE_*`. Deployment tooling rejects all local secret files except committed examples.

`npm run test:worker` bundles and runs the real Worker in Miniflare/workerd with SQLite and fake outbound services. `npm run test:e2e` serves the real Worker with mock Gateway/Turnstile services at `PW_PORT + 1`; the upstream stream script server is at `PW_PORT + 2`. No CI test makes a live inference request. Run `npm run validate`, `npm run layers`, `npm run test:worker`, and `npm run verify:all`.

## Staged release and rollback

1. Confirm Workers, SQLite Durable Objects, AI Gateway and Turnstile free-plan allowances in the account. Keep billing/paid model fallback and Gateway response caching off. Confirm the three model IDs with `npm run ai:models`. Free allowances may change; exhaustion must cause refusal, never paid inference.
2. Create an authenticated provider-native Gateway for each environment. Set `AI_GATEWAY_ACCOUNT_ID` and `AI_GATEWAY_ID` in the corresponding `wrangler.json` vars. Create separate Turnstile widgets restricted to the exact dev and production hostnames.
3. Provision **runtime** secrets separately on each Worker: `OPENROUTER_API_KEY`, `AI_GATEWAY_TOKEN`, `TURNSTILE_SECRET`, `AI_COOKIE_SECRET` (at least 32 random characters). Use the Cloudflare secret controls or `wrangler secret put` with the explicit repository config and `--env dev` / `--env ""`; never put secret values in shell arguments or build variables.
4. On dev Workers Builds set only `VITE_AI_ENABLED=true` and the public `VITE_TURNSTILE_SITE_KEY`. Keep production's public UI flag and runtime `AI_ENABLED` off. Deploy from a clean `dev` checkout exclusively with `npm run app:host:deploy:dev` or the existing Workers Builds pipeline. The SQLite `ai-v1` migration creates independent namespaces for the two Workers.
5. Accept representative OT/NT verses for all four actions, all four tracks, canonical context consistency, quota/cache behavior, Stop/disconnect, Arabic output, narrow screens, keyboard/screen-reader behavior, absence of credentials in served assets, and no Worker resource-limit errors. Record latency, failures, refusals and hit rate without questions or payloads. Exercise a runtime disable and restore on dev. Preserve a post-migration deployment version with AI disabled for rollback.
6. Revoke **every formerly browser-exposed OpenRouter key** and remove all `VITE_OPENROUTER_*`, `VITE_AI_PROVIDERS`, `VITE_AI_DAILY_CAP` and test-only build variables. Rotation is essential even though new bundles contain no credentials. Old installed clients may need the offered application update before AI works again.
7. After recorded dev acceptance, open the existing `dev` → `main` release PR, set the explicit production release gate and appropriate runtime/public settings, obtain the required verify and code-owner approval, and merge with a merge commit. Never squash the release or deploy from a task branch.

Runtime kill switch: set the relevant `AI_ENABLED` var to `"false"` in a reviewed configuration deployment. To deploy that configuration without rebuilding the frontend, use the guarded `app:host:disable` / `app:host:disable:dev` scripts from the matching clean branch; they accept only `AI_ENABLED=false`, validate existing assets, and pass `--no-build` to Wrangler. Never run a bare deploy. Alternatively restore the retained **post-migration** disabled version; do not roll back to the old browser-key build or remove the Durable Object migration.

The implementation alone does not provision account settings, revoke existing keys, deploy dev, or establish dev acceptance. Keep production gated until those operational steps have actually been completed.
