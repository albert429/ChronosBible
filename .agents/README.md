# Shared agent workflow

Quickstart for coordinating several AI agents on Bible150. Roles, skills and
templates are tracked; everything else under `.agents/` is local and ignored.

```sh
npm ci --ignore-scripts                 # once per checkout
npm run agents -- doctor                # check Node, Git, ports, profile
npm run agents -- init                  # create integration worktree and state
npm run agents -- status                # agents, branches, ports, handoffs
npm run agents -- check                 # validate catalog, roles, skills, adapters
npm run agents -- sync                  # regenerate Claude/Codex adapters
npm run agents -- create <id> --role <id> --brief brief.json
npm run agents -- handoff <id> --report report.json
npm run agents -- cleanup <id> [--apply]  # dry run unless --apply
```

## Layout

| Path                             | Purpose                                                                                       |
| -------------------------------- | --------------------------------------------------------------------------------------------- |
| `catalog.json`                   | Nine roles: `{version:1, roles:[{id,name,description,instructions,recommendedPaths,skills}]}` |
| `roles/<id>.md`                  | Concise role prompt; `name` is `bible150-<id>`                                                |
| `skills/<name>/`                 | Six canonical skills (`SKILL.md` plus optional `references/`)                                 |
| `templates/`                     | `assignment`/`handoff` JSON examples and `local-profile.example.json`                         |
| `state/`, `artifacts/` (ignored) | Registry and shared evidence; always the primary checkout's copy                              |
| `worktrees/` (ignored)           | `integration` and one worktree per task                                                       |

Roles: coordinator, product, ui-ux, bible-data, progress-storage, audio,
ai-study, deployment, qa-performance. A role's `recommendedPaths` are defaults;
the assignment's `writablePaths` decide what an agent may edit. No model is
pinned; an agent inherits the permissions of the session that launches it.

Skills: `bible150-task-coordination`, `-handoff-recovery`,
`-arabic-reader-review`, `-scripture-data-audit`, `-audio-publication`,
`-verification-release`.

Copy `templates/local-profile.example.json` to `.agents/state/local-profile.json`
and edit it; the copy is ignored. It holds `maxImplementationAgents` (up to 3),
`playwrightPortBase` (default 4400), an optional absolute `mediaRoot` outside any
worktree, and advisory `modelPreferences` (Opus, Sonnet, Sol) that no tool is
forced to follow.

## Tool discovery

Edit only the canonical sources in `.agents/`; the tool-specific copies are
generated by `npm run agents -- sync` and verified by `check`.

| Tool   | Reads                                                                                                                                               |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex  | Canonical `.agents/skills/` and generated custom agents `.codex/agents/bible150-*.toml` (`name`, `description`, `developer_instructions`; no model) |
| Claude | Generated `.claude/agents/bible150-*.md` and `.claude/skills/bible150-*/`; `CLAUDE.md` imports `AGENTS.md`                                          |

Generated files carry a `generated:` marker. Sync refuses to overwrite a file
without it, even under the `bible150-` prefix, rejects symlinks and path
traversal, and removes only stale files it generated. Other agents in the same
folders (for example `promo-video`) are never touched.

Native subagents are a convenience, not a security boundary: they run with the
permissions of the session that started them. Do not rely on a role prompt to
sandbox anything.

Optional integrations (MCP servers, global hooks, LLM calls in CI) are not
installed or required by this workflow.

## Branches and worktrees

- `.agents/worktrees/integration` holds the persistent branch
  `agents/integration`, created from an explicit `origin/dev` (or the
  `origin/<branch>` a dependency names).
- Each task gets a temporary branch `agents/<id>` and worktree from the
  integration HEAD.
- The registry and artifacts are anchored in the primary checkout (resolved from
  the Git common directory), never inside a task worktree, so every agent sees
  the same state. Handoff `artifacts` are paths under that shared
  `.agents/artifacts/`.

## Running agents

- Writers are launched by the user, with their cwd set to the assigned
  worktree. Do not use a tool's native automatic worktrees inside one; nested
  worktrees confuse ownership. Read-only reviewers may share a checkout.
- At most 3 implementation agents run at once. A shared path
  (`package.json`, lockfile, `AGENTS.md`, `.github/`, `vite.config.ts`) has a
  single owner at a time.
- A brief has `goal`, `writablePaths`, `dependencies`, `acceptanceChecks`
  ([example](templates/assignment.example.json)). A handoff has `tests`,
  `findings`, `remainingWork`, `artifacts`
  ([example](templates/handoff.example.json)); the CLI derives commits.
- The coordinator reviews each handoff, then integrates serially into
  `agents/integration` and prepares the PR to `dev`.

## Example: one task, start to finish

1. **Assign.** The coordinator writes `brief.json` (see the assignment
   template) and runs
   `npm run agents -- create plan-grid --role ui-ux --brief brief.json`. This
   creates `agents/plan-grid` and `.agents/worktrees/plan-grid` from the
   integration HEAD (or from the base a dependency names), and reserves the
   next free port block: 4400–4402 for the first task, 4403–4405 for the
   second, and so on, counted from `playwrightPortBase`.
2. **Launch.** The user starts the agent with its working directory set to
   `.agents/worktrees/plan-grid`, runs `npm ci --ignore-scripts` there, and
   uses the reserved `PW_PORT` for browser tests.
3. **Hand off.** The agent writes `report.json` and runs
   `npm run agents -- handoff plan-grid --report report.json`; evidence goes
   in the primary checkout's `.agents/artifacts/`.
4. **Merge.** The coordinator reviews the handoff against `acceptanceChecks`
   and merges `agents/plan-grid` into `agents/integration`, re-running the
   affected checks.
5. **PR.** Once the user has authorized it, the coordinator pushes
   `agents/integration` and opens the PR to `dev`.
6. **Clean up.** `npm run agents -- cleanup plan-grid` lists what would be
   removed; add `--apply` after the PR is merged.

## Isolation

- **Ports:** each worktree gets its own block of three ports from `PW_PORT`
  (the next two serve AI tests); blocks must not overlap. Never reuse a stale
  preview server.
- **Install:** `npm ci --ignore-scripts` in each worktree, so the `prepare`
  script cannot change the shared Git hooks path. Do not share `node_modules`
  or generated output (`dist/`, `dist-ai/`, `public/readings/`, `public/study/`).
- **Media:** audio binaries live durably outside any worktree (`mediaRoot` in
  the local profile) and are never committed.
- **Cleanup:** fails closed. A dry run lists what would go; unknown ignored
  files block removal, and only the named worktree and branch are touched. Never
  run a global `git worktree prune`.

## Authorization

Remote actions (push, PR, deploy, upload) happen only within what the user has
authorized in the current session; an existing authorization is honored without
re-asking for each push, and is never widened. Do not add blanket permanent
allow rules. Leave other worktrees and staged work (such as the promo video in
the primary checkout) alone.

## Git notes

Only the definitions are tracked (see `.gitignore`). Some clones exclude
`/.agents/` in `.git/info/exclude`, which hides new definition files; add them
with `git add -f` using their exact paths, and leave the local exclude as is.
`npm run agents -- doctor` warns when it finds this.
