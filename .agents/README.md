# Shared agent workflow

Quickstart for coordinating several AI agents on chronosBible. Roles, skills and
templates are tracked; everything else under `.agents/` is local and ignored.

```sh
npm ci --ignore-scripts                 # once per checkout
npm run agents -- doctor                # check Node, Git, ports, profile
npm run agents -- init                  # create integration worktree and state
npm run agents -- status                # agents, branches, ports, handoffs
npm run agents -- check                 # validate catalog, roles, skills, adapters (read-only)
npm run agents -- sync                  # regenerate Claude/Codex adapters
npm run agents -- create <id> --role <id> --brief <file|json>
npm run agents -- handoff <id> --report <file|json>
npm run agents -- cleanup <id> [--apply] [--discard-generated]  # dry run unless --apply
```

## Layout

| Path                             | Purpose                                                                                       |
| -------------------------------- | --------------------------------------------------------------------------------------------- |
| `catalog.json`                   | Nine roles: `{version:1, roles:[{id,name,description,instructions,recommendedPaths,skills}]}` |
| `roles/<id>.md`                  | Concise role prompt; `name` is `chronos-bible-<id>`                                           |
| `skills/<name>/`                 | Six canonical skills (`SKILL.md` plus optional `references/`)                                 |
| `templates/`                     | `assignment`/`handoff` JSON examples and `local-profile.example.json`                         |
| `state/`, `artifacts/` (ignored) | Registry and shared evidence; always the primary checkout's copy                              |
| `worktrees/` (ignored)           | `integration` and one worktree per task                                                       |

Roles: coordinator, product, ui-ux, bible-data, progress-storage, audio,
ai-study, deployment, qa-performance. A role's `recommendedPaths` are defaults;
the assignment's `writablePaths` decide what an agent may edit. No model is
pinned; an agent inherits the permissions of the session that launches it.

Skills: `chronos-bible-task-coordination`, `-handoff-recovery`,
`-arabic-reader-review`, `-scripture-data-audit`, `-audio-publication`,
`-verification-release`.

Copy `templates/local-profile.example.json` to `.agents/state/local-profile.json`
and edit it; the copy is ignored. Supported fields: `maxImplementationAgents`
(1–3), `playwrightPortBase` (default 4400), an optional absolute `mediaRoot`
outside the checkout and its worktrees, and `models`, an advisory map (a
`default` and optional per-role entries such as Opus, Sonnet or Sol) that the
CLI only echoes when you create a task. The base (`origin/dev`) and integration
branch (`agents/integration`) are fixed; they are not profile settings.

## Tool discovery

Edit only the canonical sources in `.agents/`; the tool-specific copies are
generated by `npm run agents -- sync` and verified by `check`.

| Tool   | Reads                                                                                                                                                                  |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex  | `AGENTS.md`, canonical `.agents/skills/`, and generated custom agents `.codex/agents/chronos-bible-*.toml` (`name`, `description`, `developer_instructions`; no model) |
| Claude | `CLAUDE.md` (imports `AGENTS.md`), generated `.claude/agents/chronos-bible-*.md` and `.claude/skills/chronos-bible-*/`                                                 |

Generated files carry a `generated:` marker outside any frontmatter. Sync
refuses to overwrite a file without it, even under the `chronos-bible-` prefix,
rejects symlinks and path traversal, writes through exclusive temporary files,
and removes only stale files it generated. Other agents in the same folders (for
example `promo-video`) and `.codex/config.toml` are never touched. `check` is
read-only: it reads repository files, needs no credentials or model CLI, and
makes no network calls.

Claude Code 2.1.302's `--safe-mode` disables `CLAUDE.md`, skills, plugins, hooks,
MCP servers and custom agents, so it cannot be used for native discovery of
these roles; use it only to troubleshoot a broken configuration. A normal
session in a trusted project, optionally with `--strict-mcp-config` to ignore
other MCP servers, discovers everything above.

Verified native discovery: Claude Code 2.1.310 exposes all 9 `chronos-bible-`
roles and 6 skills at initialization, alongside the unrelated `promo-video`
agent. Codex CLI 0.162.1 lists all 6 skills over `skills/list`; its startup
request to a local mock Responses endpoint includes all 9 custom role
identifiers in the model-visible input. These checks establish that the native
definitions are available; they did not execute a model or prove that an agent
completed a task. No paid model calls were made. Discovery can differ between
versions and clients, so smoke-test after upgrading. CI makes no model calls.

Native subagents are a convenience, not a security boundary: they run with the
permissions of the session that started them. Optional integrations (MCP
servers, global hooks, LLM calls in CI) are not installed or required by this
workflow.

## Branches and worktrees

- `init` creates the persistent branch `agents/integration` and the worktree
  `.agents/worktrees/integration` from `origin/dev`, always. The CLI never
  fetches; fetch `origin/dev` yourself first. The integration worktree leases
  the first port block.
- `create` always branches `agents/<id>` and `.agents/worktrees/<id>` from the
  current `agents/integration` HEAD. A brief's `dependencies` are task ids that
  must already be integrated (merged into `agents/integration`) or archived;
  they are not remote refs and do not change the base.
- The registry and artifacts are anchored in the primary checkout (resolved from
  the Git common directory), never inside a task worktree, so every agent sees
  the same state. Handoff `artifacts` are paths under the shared
  `.agents/artifacts/`; they must exist and lie outside the task worktree.

## Running agents

- Writers are launched by the user, with their cwd set to the assigned
  worktree. Do not use a tool's native automatic worktrees inside one; nested
  worktrees confuse ownership. Read-only reviewers may share a checkout.
- At most 3 implementation agents run at once. A shared path
  (`package.json`, lockfile, `AGENTS.md`, `.github/`, `vite.config.ts`) has a
  single owner at a time; `create` rejects overlapping `writablePaths`.
- A brief has `goal`, `writablePaths` (files or `dir/`, no globs),
  `dependencies`, `acceptanceChecks`
  ([example](templates/assignment.example.json)). A handoff has `tests`,
  `findings`, `remainingWork`, `artifacts` and optional `session`
  (`tool`, `model`, `sessionId`, `watchPath`, `startedAt`; short strings, no
  credentials) ([example](templates/handoff.example.json)). The CLI derives
  commits, requires a clean worktree, and rejects commits outside
  `writablePaths`. `status` shows each task's `watchPath`.
- A handoff with any `remainingWork` keeps the task `assigned` and blocks
  cleanup; with none, the task is `ready`, and becomes `integrated` once its
  commits are in `agents/integration`.
- The coordinator reviews each handoff, then merges serially into
  `agents/integration` and prepares the PR to `dev`.

## Example: one task, start to finish

1. **Assign.** The coordinator writes `brief.json` (see the assignment
   template) and runs
   `npm run agents -- create plan-grid --role ui-ux --brief brief.json`. It
   prints the worktree, the port block, any advisory model and the next step.
   Ports: the integration worktree holds 4400–4402, so the first task gets
   4403–4405, the next 4406–4408, and so on (the lowest block that is neither
   leased nor bound).
2. **Launch.** The user runs what `create` printed, then starts the tool from
   that directory (replace the path with your primary checkout's):

   ```sh
   cd "/path/to/chronosBible/.agents/worktrees/plan-grid" && npm ci --ignore-scripts
   PW_PORT=4403 claude --agent chronos-bible-ui-ux     # Claude Code
   PW_PORT=4403 codex -C "/path/to/chronosBible/.agents/worktrees/plan-grid"   # Codex; then ask for the chronos-bible-ui-ux agent
   ```

3. **Hand off.** The agent commits inside `writablePaths`, saves evidence under
   the primary checkout's `.agents/artifacts/plan-grid/`, and runs
   `npm run agents -- handoff plan-grid --report report.json`.
4. **Merge.** The coordinator reviews the handoff against `acceptanceChecks`
   and merges `agents/plan-grid` into `agents/integration` (from the
   integration worktree), re-running the affected checks.
5. **PR.** Within the authorization the user has given, the coordinator pushes
   `agents/integration` and opens the PR to `dev`.
6. **Clean up.** `npm run agents -- cleanup plan-grid` is a dry run; add
   `--apply` once it reports `ready` (after the work is in
   `agents/integration`).

## Isolation

- **Ports:** each worktree gets its own block of three ports from `PW_PORT`
  (the next two serve AI tests); blocks must not overlap. Never reuse a stale
  preview server.
- **Install:** `npm ci --ignore-scripts` in each worktree, so the `prepare`
  script cannot change the shared Git hooks path. Do not share `node_modules`
  or generated output (`dist/`, `dist-ai/`, `public/readings/`, `public/study/`).
- **Media:** audio binaries live durably outside any worktree (`mediaRoot` in
  the local profile) and are never committed.
- **Cleanup:** fails closed and touches only the named worktree and branch
  (`git worktree remove`, `git branch -d`); it never prunes globally. Run it
  from outside the task worktree. It is blocked by: no handoff or any
  `remainingWork`; uncommitted or untracked files; a branch that moved since the
  handoff, has no commits, or is not merged into `agents/integration`; an
  artifact that is missing or inside the worktree; and ignored files. Ignored
  files that are not vetted rebuildable output (for example a local `.env` or
  media) block removal. `--discard-generated` deletes only vetted output
  (`node_modules/`, `dist/`, `dist-ai/`, `public/readings/`, `public/study/`,
  `public/bible/`, `public/chronology/`, `test-results/`, `playwright-report/`,
  `__pycache__/`, `*.pyc`, `*.tsbuildinfo`, `.DS_Store`); without the flag such
  files also block.

## Authorization

Remote actions (push, PR, deploy, upload) happen only within what the user has
authorized in the current session; an existing authorization is honored without
re-asking for each push, and is never widened. The CLI itself never mutates a
remote. Do not add blanket permanent allow rules. Leave other worktrees and
staged work (such as the promo video in the primary checkout) alone.

## Git notes

Only the definitions are tracked (see `.gitignore`). Some clones exclude
`/.agents/` in `.git/info/exclude`, which hides new definition files; add them
with `git add -f` using their exact paths, and leave the local exclude as is.
`npm run agents -- doctor` reports ignore rules that hide definitions.
